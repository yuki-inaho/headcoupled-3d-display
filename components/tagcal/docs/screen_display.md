# ディスプレイへの実寸表示

印刷したボードは板に貼っても反りが残るのに対し、ディスプレイは平面性が極めて高い。
キャリブレーションはターゲットが平面であることを前提にするため、これは実質的な利点になる。

ただし「実寸で表示できている」ことは自動的には成立しない。次の 3 つが独立に必要で、
どれが崩れてもスケールだけが静かに間違ったまま処理が最後まで通ってしまう。

| # | 条件 | 崩れる原因 | tagcal での対処 |
|---|---|---|---|
| 1 | 画素ピッチ (px/mm) が正しい | EDID の物理サイズが丸め・未申告・嘘 | `xrandr` から取得。`--ruler` で定規と照合し `--cal` で補正 |
| 2 | タグサイズの定義が検出側と一致 | 白の quiet zone を含めて実寸と誤認（**1.25 倍**） | 黒枠外周＝`cells_per_tag` で統一し、実効値を manifest に記録 |
| 3 | 画像 1 px = 物理 1 px | HiDPI スケーリング、ピクスマップの拡大、ウィンドウのリサイズ | Qt スケーリングを無効化し、`setScaledContents(False)` で等倍配置 |

## 1. 画素ピッチの確認と校正

```bash
uv run tagcal screen list
```

```
HDMI-0 * 1920×1080  527×296 mm  3.6433 px/mm   92.5 PPI  0.15%
DP-0     1920×1080  381×214 mm  5.0394 px/mm  128.0 PPI  0.15%
DP-2     1920×1080  527×296 mm  3.6433 px/mm   92.5 PPI  0.15%
```

最右列は水平と垂直の px/mm の食い違い。EDID の丸め程度（1% 未満）なら正常で、
大きい場合は EDID を疑う。

実測校正は定規を画面に当てて行う。

```bash
# mm 目盛りを重ねて表示（表示中に r キーでも切り替わる）
uv run tagcal screen show --monitor DP-2 --ruler

# 100 mm のはずが 98.5 mm に見えたら
uv run tagcal screen show --monitor DP-2 --cal 0.985 --ruler   # 再確認
```

`--cal` は px/mm に掛かる係数で、`実測値 / 表示値` を掛けていく。
EDID を使わず実測値を直接与えるなら `--px-per-mm` を使う。

## 2. タグサイズの定義（最重要）

tag36h11 の構造:

```
+-----------------------------+  <- 白 quiet zone（検出に必要／サイズには含めない）
|  +-----------------------+  |
|  |#######################|  |  <- 黒枠 1 セル
|  |###   6x6 データ    ###|  |
|  |#######################|  |
|  +-----------------------+  |
+-----------------------------+
   |<------ 8 セル ------->|      = tag_size
```

- データ 6×6 + 黒枠 1 セル = **合計 8 セル**。この外周一辺が `tag_size`。
- 配布されている AprilTag 画像は外側に白 1 セルを含む 10×10 のことがある。
  これを実寸としてしまうと 10/8 = **1.25 倍**のスケール誤差が距離推定に丸ごと乗る。
- ファミリごとのセル数: `tag16h5` → 6、`tag25h9` → 7、`tag36h10` / `tag36h11` → 8。
  `AprilGridBoard.cells_per_tag` が辞書の `markerSize` と `border_bits` から算出する。

OpenCV の aruco はコーナーとして黒枠最外周ピクセルの*中心*を返すため、
合成画像では N px の黒領域が N−1 px として検出される。実カメラ画像では境界がぼけて
サブピクセル推定されるためほぼ消えるが、画面ピクセルを直接扱う検証時は
1 px（92.5 PPI なら 0.27 mm）を意識する。`tests/test_screen.py` はこの許容込みで検証している。

## 3. セルを整数 px に丸めるか（`--snap`、既定 ON）

px/mm は一般に無理数なので、「切りの良い mm」と「セル整数 px」は両立しない。

DP-2（3.6433 px/mm）で 40 mm のタグを要求した場合:

| モード | tag | セル実幅 | 実サイズ | セル境界のばらつき |
|---|---|---|---|---|
| `--snap`（既定） | 144 px | 18 px 均一 | 39.5250 mm | 0 |
| `--no-snap` | 146 px | 18/19 px 混在 | 40.0740 mm | 0.2745 mm |

**要求値からずれること自体は問題ではない。** 表示した実寸は `pattern.json` に
そのまま書き込まれ、検出・キャリブレーションはその値を使う。
一方セル幅の不均一はタグ座標系そのものの歪みなので、`--snap` が原理的に有利。

ばらつきの絶対値は常に 1 px だが、**相対誤差はタグが小さいほど深刻**になる。
100 mm で 2.2%、40 mm で 5.6%、20 mm では 11%。小さいタグ・低 PPI ほど `--snap` を使う。

切りの良い実寸に近い候補を知りたい場合:

```bash
uv run tagcal screen suggest --monitor DP-2 --tag-size-mm 40
```

## 4. manifest がスケールの単一の情報源

`tagcal screen show` は表示と同時に、量子化後の実寸を書いた `pattern.json` を出力する。

```json
{ "pattern": { "tag_size_mm": 39.525, "gap_mm": 9.88125, "display_scale": 1.0 } }
```

印刷ボード用の `tagcal pattern confirm-scale` は「公称値 × `display_scale`」で実寸を表すが、
画面表示では snap によってタグと間隔が別々に丸められるため単一の倍率では表せない。
そこで寸法自体を実効値へ書き換え、`display_scale` は 1.0 に固定している。

この manifest をそのまま `tagcal process` に渡せば、スケールは一貫する。

```bash
uv run tagcal process capture.mp4 artifacts/screen/pattern.json artifacts/session
```

## 5. モニタ表示特有の注意

### 有利な点

- **平面性が極めて高い**。印刷紙を板に貼る方式より圧倒的に良い。
- サイズ・ID を即座に変更でき、スケール誤差の切り分けが速い。

### 注意すべき点

| 項目 | 症状 | 対処 |
|---|---|---|
| 輝度過多 | 白が飽和して黒枠が滲む、検出率低下 | 輝度を 30〜50% に下げ、カメラは露出固定 |
| ガラス厚 | 距離が一様に 1〜2 mm 短く出る | 液晶面はガラス表面の奥。高精度用途では基準面を意識する |
| PWM 調光 + ローリングシャッター | 横縞のバンディング | 輝度を上げて PWM を止める、露光時間を延ばす |
| リフレッシュ非同期 | 描画途中の像が写る | 露光時間 > 1/リフレッシュレート（60 Hz なら 16.7 ms 以上） |
| モアレ | 遠距離で格子縞 | わずかにデフォーカス、距離・角度を変える |
| 反射 | 照明の映り込みで白飛び | ノングレアパネル、照明位置を変える |
| 視野角 | 斜めで輝度・コントラスト低下 | IPS を使う。TN は大角度で破綻しやすい |
| 色温度調整 | Night Light / Redshift で白色点が動く | OFF にする |
| サブピクセル構造 | エッジ位置に微小バイアス | グレースケール化で緩和 |

キャリブレーションでは画面全体をカバーする姿勢が必要なため、
**ボードを動かすのではなくカメラを動かす**運用になる点に注意する。
画面が固定されている以上、カメラ側を上下左右へ振り、傾け、距離を変える。
