# 添付資料の確認結果

## 1. 結論

三つの添付物を確認した結果、実装に必要な構成要素と較正方法は十分に記述されていましたが、
実測済みのカメラ・ディスプレイ外部姿勢ファイルは含まれていませんでした。

特に、次の数値は添付物から確定できません。

- ディスプレイ有効表示領域中央からカメラ光学中心までの高さ
- カメラ光軸がディスプレイ法線から何度下を向くか
- カメラ光学中心がディスプレイ面より何cm手前にあるか
- カメラ・ディスプレイ間の完全な6自由度変換

会話記録には、これらを入力値・弱い事前制約・縦方向ターゲットからの推定対象として扱う
設計が示されています。したがって、本実装は数値を捏造せず、次の二経路を用意しました。

1. `camera_mount` に高さ・前後・ピッチ等を直接入力する。
2. `camera_to_display_matrix` に外部較正済み4×4行列を入力する。

デモは人工値20.0 cm、2.5 cm、10.0°を使い、プロファイル出自を
`synthetic_demo_not_measured` としています。

## 2. 会話記録

対象: `ChatGPT-顔認識_3D_ビュー (3).md`

### 抽出した要件

- 用語上の「顔認識」は人物同定ではなく、顔・眼位置追跡として扱う。
- 単眼映像から顔・眼ランドマークを取得し、PnPで頭部姿勢、左右眼球中心、両眼中点を得る。
- カメラ座標からディスプレイ座標へ変換し、両眼中点を仮想カメラ位置として非対称投影する。
- 表示対象は最初に `bunny.pcd` とする。
- ディスプレイ座標系は中央原点、+X右、+Y上、+Z画面法線方向とする。
- ハードウェアプロファイルと利用者プロファイルを分離する。
- 横3点だけでは上下方向・ロール・傾斜を拘束できない。最低5点、精度評価には3×3の9点を使う。
- 頭部を3Dポインターとして、既知画面点へ向く複数のレイを取得し、画面姿勢を最適化する。
- 通常実行時に必要なのは両眼中点であり、視線方向は必須ではない。
- 姿勢JSONと映像を別経路にし、映像はバイナリ配信する。

### 実装への対応

| 会話要件 | 実装 |
|---|---|
| 両眼中点による非対称投影 | `geometry.py`, `renderer.js` |
| カメラ・画面座標変換 | `CameraMount`, 4×4 `camera_to_display_matrix` |
| 5点/9点較正 | `calibration.py`, 9点×4姿勢の合成試験 |
| 頭部レイ残差 | 点とレイの直交距離をrobust least squaresで最小化 |
| ハードウェア/利用者分離 | `HardwareProfile`, `UserProfile` |
| 映像と姿勢の分離 | `/ws/camera`, `/ws/pose` |
| bunny.pcd | 本物の Stanford Bunny（`bun_zipper` 再構成、35,947頂点）。当初はオリジナル人工PCD 13,810点（`scripts/generate_bunny.py`）だったが、2026-08-17 に `scripts/import_stanford_bunny.py` で実データへ差し替え。出典・ライセンスは `docs/input_manifest.md` 参照 |

## 3. FaceMesh追跡リポジトリ

対象: `facemesh_tracking_reconstruction-main.zip`

### 確認した構成

```text
YOLOv8-Face
  → BBox + 5点整列キーポイント
  → FaceMesh V2_478
  → 478×3ランドマーク（末尾10点は虹彩）
```

主な設計上の利点:

- `FaceDetector` と `LandmarkEstimator` がProtocolで分離され、差し替え可能。
- 元画像ピクセル座標を維持するデータモデル。
- 5点キーポイントで顔クロップを正立させるため、頭部ロールに強い。
- CUDA/CPU/TensorRTのプロバイダー選択を実行層へ隔離。
- 合成・偽実装を使った単体試験が可能。

実行制約:

- Python 3.10限定。
- `onnxruntime-gpu==1.18.0`。
- CUDA 11.8、cuDNN 8系を仮想環境内に持つ構成。
- モデルは初回取得であり、GPU・ネットワーク・対象カメラ依存。

本実装では、同じ二段分離と値オブジェクトの考え方を維持し、
`FaceMeshTrackingProvider` を任意の追跡実装として隔離しました。合成モードはモデル取得なしで
全APIとUIを試験できます。

## 4. AprilTagカメラ較正リポジトリ

対象: `apriltag-camera-calibrator-main.zip`

### 確認した機能

- AprilTagグリッドによるカメラ内部較正。
- ディスプレイへ実寸表示するパターン生成。
- EDID由来px/mm、定規補正、整数セルへのsnap。
- 動画記録、キーフレーム選択、外れ値除外、再投影誤差レポート。
- `calibration.json`、OpenCV YAML、ROS CameraInfo YAMLの出力。
- `uv`、`justfile`、pytest、ruff、型検査を持つ。

特に重要なスケール注意:

- tag36h11の実寸は黒枠外周8セルであり、白quiet zoneを含む10セルを使うと1.25倍誤る。
- 画面表示では、要求mmではなく量子化後の実効寸法をmanifestの単一情報源にする。
- HiDPI拡大やウィンドウリサイズを避け、画像1pxと物理1pxを一致させる。

### 対象外

このリポジトリの較正結果はカメラ内部パラメータ `K, D` です。カメラとディスプレイの
相対位置・姿勢は出力しません。したがって、本実装の `import-tagcal` は内部パラメータだけを
統合し、外部姿勢を独立項目として残します。

## 5. 実装上の判断

### ブラウザー依存

ネットワークなしでも再現できるよう、Node/npm/CDN依存を除きました。ブラウザー表示は
ES ModulesとWebGL2で実装し、PCDはASCII形式を直接読みます。WebGL2が管理ポリシー等で
無効な場合は、同一のスクリーン交差式を使うCanvas2Dへ自動切替します。

### bunny.pcd

外部のStanford Bunnyを再配布せず、楕円体表面を決定的に標本化したオリジナルの
bunny-like PCDを生成しています。生成元は `scripts/generate_bunny.py` です。

### 実測値と人工値の分離

人工値はプロファイル出自、UI警告、README、テスト報告で明示しています。較正APIが返す
精度値も「人工データの真値に対する復元誤差」であり、実機精度とは扱いません。
